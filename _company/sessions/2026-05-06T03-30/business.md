# 🚀 MVP 기능 명세 초안: 관계 기반 모금 및 아카이빙 시스템 (Collect)

본 문서는 Researcher의 시장 분석과 Business의 수익화 모델을 통합하여, **관계 그래프 분석 API** 개발을 위한 MVP 핵심 기능(F1~F5)과 초기 수익화 구조(Transaction Fee 및 레벨 시스템)를 명세합니다.

## 1. 핵심 기능 정의 (F1~F5) 및 데이터 모델 매핑

사용자의 **관계 심리적 가치(F1~F5)**를 데이터베이스의 핵심 속성으로 정의하고, 이를 기반으로 관계 그래프 분석 API가 제공할 핵심 결과물을 명세합니다.

| 기능 ID | 기능 명칭 | 사용자 액션 (Front-end) | 데이터 모델 매핑 (Back-end) | API 필요성 |
| :--- | :--- | :--- | :--- | :--- |
| **F1** | **관계 심리 가치 측정** | 모금 시작 시, 관계의 감정적 맥락을 입력하여 점수 부여 (F1~F5) | `Relationship` 테이블에 `F1`~`F5` 속성 저장 | 관계 데이터 입력 및 저장 |
| **F2** | **관계 시간 흐름 아카이빙** | 관계가 형성된 시점부터 현재까지의 시간적 흐름(타임라인) 시각화 | `Relationship` 테이블에 `Start_Date`, `Update_History` 저장 | 시간 기반 쿼리 및 시각화 데이터 제공 |
| **F3** | **공유 활성화 (모금)** | 특정 관계를 기반으로 모금 캠페인 생성 및 참여자 모집 | `Collection` 테이블과 `Relationship` 테이블 연결 | 모금 활동 및 참여자 관리 |
| **F4** | **관계 그래프 분석** | 전체 관계의 심리적 가치(F1~F5)를 종합하여 관계 분석 점수 산출 | **핵심 API 엔드포인트** (`/analyze/relationship/{id}`) | 관계의 총체적 가치 시각화 |
| **F5** | **레벨 및 보상 시스템** | 관계의 질적 가치(F4 결과)에 따라 등급(Level) 부여 및 혜택 제공 | `User_Level` 테이블 및 `Relationship` 테이블 연결 | 수익화 로직 적용 및 보상 지급 |

## 2. 초기 수익화 모델 (Transaction Fee 및 레벨 시스템) 명세

수익화는 **관계의 질적 가치(F4 분석 결과)**에 따라 차등화된 수수료 구조를 적용하여, 사용자가 돈보다 관계에 집중하도록 유도합니다.

### A. 수수료 구조 (Transaction Fee)

| 단계 | 조건 | 수수료율 (Transaction Fee) | 목적 |
| :--- | :--- | :--- | :--- |
| **F1, F2 (기본 아카이빙)** | 관계 데이터 생성 및 시간 기록 | **0%** (무료) | 초기 진입 장벽 제거, 데이터 축적 유도 |
| **F3 (모금 활성화)** | 관계 기반 모금 캠페인 생성 시 | **1.0%** (기본 수수료) | 플랫폼 활성화 및 최소한의 수익 확보 |
| **F5 (레벨 달성)** | 특정 관계 분석 점수(F4) 달성 시 | **1.0% + 추가 보너스** (Level 기반) | 높은 가치 관계에 대한 보상 및 프리미엄 기능 유도 |

### B. 레벨 시스템 (Level System)

레벨은 사용자가 축적한 관계의 깊이와 플랫폼 기여도에 따라 부여되며, 이는 **F4 관계 분석 점수**에 직접적으로 연동됩니다.

| 레벨 | 요구되는 평균 관계 점수 (F4 기반) | 혜택 (Reward) | 목표 |
| :--- | :--- | :--- | :--- |
| **Bronze** | 1.0 ~ 2.5 | 기본 아카이빙 무제한 | 초기 사용자 유지 |
| **Silver** | 2.6 ~ 4.0 | 모금 수수료 0.5% 할인, 기본 혜택 | 활성 사용자 전환 유도 |
| **Gold** | 4.1 ~ 5.0 | 모금 수수료 0.25% 할인, 프리미엄 아카이빙 기능 잠금 해제 | 핵심 가치 사용자 확보 |
| **Platinum** | 5.0 이상 | 관계 그래프 심층 분석 리포트 무제한, VIP 커뮤니티 접근 | 최고 가치 사용자 유지 및 수익 극대화 |

## 3. API 엔드포인트 명세 초안 (Developer 참고용)

개발 착수를 위해 관계 그래프 분석 API에 필요한 최소한의 엔드포인트와 데이터 흐름을 정의합니다.

**Endpoint 1: 관계 데이터 입력 및 저장**
*   **POST `/api/relationships`**: 새로운 관계(Relationship) 및 심리 가치(F1~F5)를 저장합니다.
    *   *Input:* Relationship Data, F1, F2, F3, F4, F5
    *   *Output:* Relationship ID

**Endpoint 2: 관계 그래프 분석 (핵심)**
*   **GET `/api/analyze/relationship/{id}`**: 특정 관계 ID에 대한 종합 분석 점수를 반환합니다.
    *   *Input:* Relationship ID
    *   *Output:* `{ "relationship_id": "...", "overall_score": X.X, "f1_score": Y, "f2_timeline": [...] }`

**Endpoint 3: 모금 및 수익화 연동**
*   **POST `/api/collections/{id}/fee`**: 모금 캠페인에 대한 최종 수수료를 계산하고 기록합니다.
    *   *Input:* Collection ID, Status
    *   *Output:* `{ "fee_amount": Y, "fee_rate": Z, "level_achieved": "Gold" }`
